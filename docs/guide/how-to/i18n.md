# 国际化

本文解决两个独立的国际化需求：设计器界面文案，以及节点（物料）文案。它们由两个不同的 `I18n` 实例驱动，
需要分别配置。

| 类型     | 来源                          | 读取方式                   |
| -------- | ----------------------------- | -------------------------- |
| UI 文案  | `Designer` / `ConfigProvider` | `useText()`、`TextWidget`  |
| 节点文案 | `engine.registry`             | `node.getMessage('title')` |

## 配置 UI 文案

在 `Designer` 或 `ConfigProvider` 上传入 `locale`、`fallbackLocale` 与追加文案：

```tsx
<Designer
  engine={engine}
  locale="en-US"
  fallbackLocale="en-US"
  messages={{
    'zh-CN': { actions: { save: '保存' } },
    'en-US': { actions: { save: 'Save' } },
  }}
>
```

`messages` 会合并到内置文案之上，不会覆盖未声明的 token。

## 在组件里读取文案

```tsx
import { observer, useText } from '@formvk/designable-react'

export const SaveButton = observer(() => {
  const t = useText()
  return <button type="button">{t('actions.save', 'Save')}</button>
})
```

第二个参数是缺失时的默认文案。也可以直接使用 `TextWidget`：

```tsx
import { TextWidget } from '@formvk/designable-react'

<TextWidget token="actions.save" />
<TextWidget defaultMessage="Save" />
<TextWidget>{{ 'zh-CN': '保存', 'en-US': 'Save' }}</TextWidget>
```

`useText` 内部订阅语言变化，切换语言后组件会自动重渲染。

## 运行时切换 UI 语言

`locale` 变化时 `Designer` 会调用内部 i18n 的 `setLanguage`。也可以在任意子组件中命令式切换：

```tsx
import { useI18n } from '@formvk/designable-react'

const i18n = useI18n()
i18n.setLanguage('en-US')
```

## 配置节点文案

节点文案由 Behavior 的 `designerLocales` 提供：

```ts
createBehavior({
  name: 'Input',
  selector: 'Input',
  designerLocales: {
    'zh-CN': { title: '输入框', description: '基础输入框' },
    'en-US': { title: 'Input', description: 'Basic input' },
  },
})
```

读取：

```ts
node.getMessage('title') // 按注册表当前语言返回
```

`NodeTitleWidget` 是现成的标题渲染组件：

```tsx
<NodeTitleWidget node={node} />
```

## 同步两套语言

节点文案的语言来自 `engine.registry`，与 `Designer` 的 `locale` 相互独立。只切换 `Designer` 的 `locale`，
节点标题不会变化。需要同步时：

```tsx
import { useEffect } from 'react'

useEffect(() => {
  engine.registry.setDesignerLanguage(locale)
}, [engine, locale])
```

`engine.registry.setDesignerLanguage()` 会触发 `node.getMessage()` 的响应式更新。

## 追加与覆盖文案

除了 `messages`，也可以直接操作 i18n 实例：

```ts
i18n.registerLocales({
  'ja-JP': { actions: { save: '保存する' } },
})
```

合并是按语言、按 token 深度合并；同名 token 后注册的覆盖先注册的。

## 语言回退顺序

`t()` 的查找顺序：

1. 当前语言。
2. `fallbackLanguage`。
3. 任意包含该 token 的语言。
4. 调用方传入的 `defaultMessage`。
5. token 本身。

## 验证

1. 将 `locale` 从 `zh-CN` 切到 `en-US`，面板与工具栏文案变化。
2. 同步调用 `setDesignerLanguage` 后，节点标题也变化。

## 注意事项

- 语言代码会统一为小写连字符格式（如 `zh-CN` → `zh-cn`），注册时不必手动转换。
- `Designer` 的 `messages` 只影响 UI 文案，不影响节点文案。
- 节点文案的默认标题是 `componentName`，`designerLocales.title` 缺失时会回退到它。
